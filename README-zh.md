# 结果契约 v0 — 按结果付费，你自己验

最小可复制契约：用来买/卖 **AI 交付的活**（数据清洗、研究、抓取、审计、修 bug），
让买家不用信任卖家也能验证交付物，让卖家能诚实说出自己不承诺什么。

> 为什么做：AI 服务市场大多在卖工具（"给你模型访问权"）或卖说法（"我们做对了"）。
> 买家真正要的是**结果**，而结果需要三样市场很少写下来的东西：
> 可证伪的定义、验证配方、诚实的覆盖声明。这张模板把三样写下来。

## 六条

1. **结果** — 一句话，可证伪。不是"高质量增强数据"，是"对 N 行中的每一行：URL 列
   从 200 响应填充，或写进失败清单"。陌生人能检验的才是结果；不能检验的是主张。
2. **检验** — 一个陌生人可以重跑的精确流程（抽样方法、比对什么、什么算通过）。
   买家不需要卖家的保证——重跑一遍拿到同样的判定即可。
3. **覆盖** — 交付了什么、没交付什么，用数字说：
   "40 行里 34 行；6 行失败并点名原因（403/登录墙/源已死）"。说真覆盖率是卖点不是缺陷。
   报 100% 的要么是运气要么是撒谎。
4. **价格** — 绑结果，不绑工时：按验证通过的单元固定价，或验收后付。
   这才是"结果即服务"而不是"工时即服务"：卖家扛风险，买家为产出付费。
5. **失败条款** — 检验不通过时怎么办：按已验证单元部分付款、重跑窗口、或买家走人。
   事先约定，不是事后谈。
6. **边界** — 这份契约不覆盖什么（版权源可用性、范围外承诺、无法检验的"质量"）。
   写明边界才能让其他条诚实。

## 来源认证（推荐）

每项交付物携带自己的证据：来源 URL、抓取时间戳、生产者身份。
这通常是契约里最便宜的一行，也是被坑过一次的买家最看重的一行。

## 实例

见 `案例-UK数据.md`：一个 26,811 行的英国企业数据增强任务的完整演练——

卖家预先报出失败率，而不是承诺 100%。
